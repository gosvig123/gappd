After a code change, run the relevant tests and build checks. Once validation passes, commit the completed changes and push to the current branch. Do not push if validation fails. Never force-push.

## Isolated desktop UI checks

- Do not launch a packaged Gappd build with only `HOME` or `productName` changed: Electron still uses `~/Library/Application Support/gappd-desktop`. For a packaged probe, use a fresh bundle ID, a fresh `HOME`, and `--user-data-dir=/private/tmp/<probe>/electron-data`. The startup permission migration hard-codes `dev.gappd.desktop`, so block its `tccutil reset` with a probe-only PATH stub; never reset the installed app's permission for a probe. Confirm child processes use the probe user-data directory and the backend created its DB under the probe home **before any UI action**. Use a fresh user-data directory after each ad-hoc rebuild; reusing one can block Electron in macOS Keychain. A different probe bundle ID does not prove installed-app permission attribution.
- For a development UI check, run `npm run dev:prepare` from `desktop/` (it builds the backend and native helpers, then writes `build/runtime-assets.json`; `dev:start` and `dev-ui.sh` refuse to start until that file lists every asset and each one exists). Then create a **new** absolute directory under `/private/tmp`, then run `build/gappd selected-fixture bootstrap /private/tmp/<new-dir>/fixture`. Make its `electron-user-data` directory and set `GAPPD_SELECTED_FIXTURE_PROFILE` to that fixture path. Never use a real user profile.
- Run `bash desktop/scripts/dev-ui.sh` from the repo root with that environment variable. It binds Electron DevTools only to `127.0.0.1:9337`; change `GAPPD_UI_CDP_PORT` if that port is occupied. Vite uses `127.0.0.1:5173` with strict port binding, in `npm run dev:start` too, so a busy port fails instead of loading another app's dev server into the Gappd window; set `GAPPD_UI_VITE_PORT` for these scripts and `dev:start` if another app owns that port. From `desktop/`, use `node scripts/ui-cdp.mjs inspect`, `click-text 'Settings'`, `click-text 'Screen video: Off'`, or `click-prefix 'Stop ·'`. The helper sends trusted mouse events through CDP and refuses to run without the fixture marker. Do not use it for passwords, payment details, permission grants, or other sensitive controls.
- For a UI, theme, or contrast review, run `node scripts/ui-review.mjs /private/tmp/<new-dir>/review` from `desktop/` with the same environment. It captures every view in dark and light themes at 1280x800 and 960x640, then writes `index.html` (contact sheet) and `findings.json`. The audit measures WCAG AA contrast on rendered colours (a gradient counts at its worst stop) and lists controls without an accessible name. Electron's CDP has no `Audits.checkContrast`. Single steps: `ui-cdp.mjs theme light`, `screenshot <file.png> [WIDTHxHEIGHT]`, `audit`, `key Escape`. The view list uses the selected fixture's labels, so update it in `ui-review.mjs` when navigation labels change. The fixture adds six fictional review Meetings across recent days (one failed, one transcript only). In a fixture session, Electron returns a fictional Google Calendar day built relative to the current time (`desktop/src/main/selected-fixture-calendar.ts`). A fixture toast about Local AI setup can cover content; dismiss it with `click-prefix 'Dismiss Local AI'` before screenshots.
- Storage compaction: the desktop main process runs `gappd app meetings compact-storage --json` 2 minutes after start and then every 10 minutes on AC power. It removes leftover `chunks/` folders of Meetings that are not recording, then converts one idle Meeting's WAVs to FLAC with `/usr/bin/afconvert`, or else compacts one Screen video. It skips work on battery power, so run the command by hand to test on battery. FLAC speaker clips need `GAPPD_DIARIZER_BIN` (`gappd-diarizer --pcm16 <file> <start-frame> <frame-count>`). Opening a selected-fixture profile resets fixture Meetings to `captured`; to test a recording Meeting, insert a separate row. To check it without the picker, copy a real `screen.mov` (with its `mic.wav` and `system.wav`) into `<fixture>/backend-home/.gappd/sessions/<dir>`, set one fixture Meeting's `audio_path`, `video_state='ready'`, `video_file='screen.mov'` and video/audio host times in `<fixture>/backend-home/.gappd/db.sqlite`, then run the command with `HOME=<fixture>/backend-home`. A done movie gets an empty `screen.compacted` marker. The export helper runs directly as `build/gappd-export <video> <mic> <system> <out.mp4> <videoStartHostSec> <micStartHostSec> <systemStartHostSec>`.
- CDP controls the Electron renderer, not the macOS ScreenCaptureKit picker or system permission prompts. A human must handle those when needed. Use only isolated data for UI checks. A packaged probe can prove replay, export, deletion, and quit paths, but a distinct bundle ID cannot prove installed-app permission attribution or perceptual speech sync. Record each remaining release gate by its own evidence.

## Cloud tests

- Cloud database tests need PostgreSQL 15 or newer (migration 005 uses `security_invoker`); Homebrew on this Mac has 14. Start a disposable `postgres:18` container on a loopback port and set the four `TEST_*` URLs listed in `cloud/README.md` (Local/CI checks). Without them the database tests skip and `TestRealCopiesRequireTheUnionView` fails.
