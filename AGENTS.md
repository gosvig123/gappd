After a code change, run the relevant tests and build checks. Once validation passes, commit the completed changes and push to the current branch. Do not push if validation fails. Never force-push.

## Isolated desktop UI checks

- Do not launch a packaged Gappd build with only `HOME` or `productName` changed: Electron still uses `~/Library/Application Support/gappd-desktop`. For a packaged probe, use a fresh bundle ID, a fresh `HOME`, and `--user-data-dir=/private/tmp/<probe>/electron-data`. The startup permission migration hard-codes `dev.gappd.desktop`, so block its `tccutil reset` with a probe-only PATH stub; never reset the installed app's permission for a probe. Confirm child processes use the probe user-data directory and the backend created its DB under the probe home **before any UI action**. Use a fresh user-data directory after each ad-hoc rebuild; reusing one can block Electron in macOS Keychain. A different probe bundle ID does not prove installed-app permission attribution.
- For a development UI check, run `npm run dev:prepare` from `desktop/` (it builds the backend and native helpers, then writes `build/runtime-assets.json`; `dev:start` and `dev-ui.sh` refuse to start until that file lists every asset and each one exists). Then create a **new** absolute directory under `/private/tmp`, then run `build/gappd selected-fixture bootstrap /private/tmp/<new-dir>/fixture`. Make its `electron-user-data` directory and set `GAPPD_SELECTED_FIXTURE_PROFILE` to that fixture path. Never use a real user profile.
- Run `bash desktop/scripts/dev-ui.sh` from the repo root with that environment variable. It binds Electron DevTools only to `127.0.0.1:9337`; change `GAPPD_UI_CDP_PORT` if that port is occupied. Vite uses `127.0.0.1:5173` with strict port binding, in `npm run dev:start` too, so a busy port fails instead of loading another app's dev server into the Gappd window; set `GAPPD_UI_VITE_PORT` for these scripts and `dev:start` if another app owns that port. If the Electron window is fully covered by other windows, Chromium reports `document.visibilityState` as `hidden` and drops CDP mouse input: `ui-cdp.mjs click-text` prints `Clicked` but nothing happens. Check `document.visibilityState` before you suspect the app. From `desktop/`, use `node scripts/ui-cdp.mjs inspect`, `click-text 'Settings'`, `click-text 'Screen video: Off'`, or `click-prefix 'Stop ·'`. The helper sends trusted mouse events through CDP and refuses to run without the fixture marker. Do not use it for passwords, payment details, permission grants, or other sensitive controls.
- For a UI, theme, or contrast review, run `node scripts/ui-review.mjs /private/tmp/<new-dir>/review` from `desktop/` with the same environment. It captures every view in dark and light themes at 1280x800 and 960x640, then writes `index.html` (contact sheet) and `findings.json`. The audit measures WCAG AA contrast on rendered colours (a gradient counts at its worst stop) and lists controls without an accessible name. Electron's CDP has no `Audits.checkContrast`. Single steps: `ui-cdp.mjs theme light`, `screenshot <file.png> [WIDTHxHEIGHT]`, `audit`, `key Escape`. The view list uses the selected fixture's labels, so update it in `ui-review.mjs` when navigation labels change. The fixture adds six fictional review Meetings across recent days (one failed, one transcript only). In a fixture session, Electron returns a fictional Google Calendar day built relative to the current time (`desktop/src/main/google/fixture-calendar.ts`). Background Calendar sync (`desktop/src/main/google/calendar-refresh.ts`: every 5 min, 15 min on battery, on window focus, and 30 s after wake) does nothing in a fixture session; check it with a one-off script against `GoogleCalendarServiceCore` and a fake `CalendarApi`. A fresh fixture shows the Set up Gappd card above every view until the optional "Meeting notes with AI" and "Share anonymous usage counts" steps are answered: `click-text 'Not now'` skips notes (remembered in the fixture's `electron-user-data`), `click-text 'Download 1.6 GB'` downloads the notes model there, and `click-text "Don't share"` or `click-text 'Share'` answers the usage step (saved in `electron-user-data/usage-report.json`). A development run never sends a Usage report unless `GAPPD_USAGE_REPORT_URL` is set; then the first check runs 10 s after launch. To watch a send, start `cloud/cmd/server` against a disposable PostgreSQL (see Cloud tests), answer Share, quit, set `"day"` in `usage-report.json` to yesterday, relaunch, and read `usage_daily` ([usage reports](docs/usage-reports.md)). The fixture Meetings have no transcript segments, so the speaker panel is empty: to check speaker labels or voice suggestions, insert fictional `segments` (`speaker_source` `system`, keys `Speaker N`), set `diarization_state='completed'`, and add `meeting_speaker_embeddings` rows (256 values, model `db.VoiceModel`). The app's recognition loop runs every 60 s. To check the optional Gmail and Contacts access, add `GAPPD_GMAIL_REVIEW=1 GAPPD_CONTACTS_REVIEW=1` to the `dev-ui.sh` environment: the fixture account then has both, People shows **Import Google contacts** (fictional contacts from `selectedFixtureContacts`), and each Person with an email gets an **Email** button (fictional threads only for `avery.chen@example.test`). Packaged builds ignore these switches. Gappd finds Codex, Claude Code, and Pi itself (`gappd app config find-agents --json`); the fixture's isolated `HOME` has no agent sign-in, so each agent shows "not signed in". Claude Code ties its keychain sign-in to its config path, so it stays signed out under any other `HOME`, and so do Pi models from the claude-bridge extension. To make real agent notes in a fixture, link `~/.pi` (or `~/.codex`) and `~/.local/bin` into `<fixture>/backend-home`, choose a Pi model from a built-in provider such as `openai-codex`, set a Meeting that has a transcript to `processing_status='pending'`, and wait for the 60 s drain retry. A failed agent call is requeued without a message; to see its error, run the notes pipeline (`ai.NewPipeline(...).Run`) in a one-off script. `ui-cdp.mjs` cannot change a `<select>`; attach `agent_browser` with `--cdp 9337` and use `select`. Launch only reads recording access; macOS prompts fire on the card's Allow button or on Record.
- Storage compaction: the desktop main process runs `gappd app meetings compact-storage --json` 2 minutes after start and then every 10 minutes on AC power. It removes leftover `chunks/` folders of Meetings that are not recording, then converts one idle Meeting's WAVs to FLAC with `/usr/bin/afconvert`, or else compacts one Screen video to AV1 with the bundled `gappd-ffmpeg` (`GAPPD_FFMPEG_PATH`). It skips work on battery power, so run the command by hand to test on battery. FLAC speaker clips need `GAPPD_DIARIZER_BIN` (`gappd-diarizer --pcm16 <file> <start-frame> <frame-count>`). Opening a selected-fixture profile resets fixture Meetings to `captured`; to test a recording Meeting, insert a separate row. To check it without the picker, copy a real `screen.mov` (with its `mic.wav` and `system.wav`) into `<fixture>/backend-home/.gappd/sessions/<dir>`, set one fixture Meeting's `audio_path`, `video_state='ready'`, `video_file='screen.mov'` and video/audio host times in `<fixture>/backend-home/.gappd/db.sqlite`, then run the command with `HOME=<fixture>/backend-home`. Compaction writes `screen.mp4` (AV1, CRF 40, keyframe every 450 frames, every source timestamp kept) beside `screen.mov`, decodes it with dav1d to check that it has every frame, then removes the `.mov`; the DB still records `video_file='screen.mov'`, and `video.AssetPath` and `meeting-media.ts` prefer the `.mp4`. A done movie gets a `screen.compacted` marker that holds the compaction version (`av1-crf40`); HEVC movies marked `keyframes-10s` or `keyframes-30s` are also done, because another lossy pass would cost quality. Encoding takes about 1/7 of the movie length on an M4 (a 4-minute clip took 33 s) at about 700 MB of memory. Build the encoder with `npm run prepare:ffmpeg` from `desktop/` (part of `dev:prepare` and `dist`; needs `brew install meson ninja nasm`); it is a static LGPL ffmpeg 9 with SVT-AV1 and dav1d, pinned in `desktop/src/shared/runtime-manifest.json`, written to `desktop/resources/ffmpeg/` with its licenses. Export of an AV1 movie runs `gappd-ffmpeg` (dav1d decode, H.264 VideoToolbox encode) instead of `gappd-export`, so it needs no AV1 hardware decoder. The export helper runs directly as `build/gappd-export <video> <mic> <system> <out.mp4> <videoStartHostSec> <micStartHostSec> <systemStartHostSec>`.
- CDP controls the Electron renderer, not the macOS ScreenCaptureKit picker or system permission prompts. A human must handle those when needed. Use only isolated data for UI checks. A packaged probe can prove replay, export, deletion, and quit paths, but a distinct bundle ID cannot prove installed-app permission attribution or perceptual speech sync. Record each remaining release gate by its own evidence.

## Cloud tests

- Cloud database tests need PostgreSQL 15 or newer (migration 005 uses `security_invoker`); Homebrew on this Mac has 14. Start a disposable `postgres:18` container on a loopback port and set the four `TEST_*` URLs listed in `cloud/README.md` (Local/CI checks). Without them the database tests skip and `TestRealCopiesRequireTheUnionView` fails.
- To open a pool on another database, build the URL (`url.Parse(dsn)`, set `Path = "/"+name`). Do not change `pgxpool.Config.ConnConfig.Database` and then call `Config.ConnString()`: it returns the original DSN, so the test connects to the wrong database and can pass for the wrong reason.

## Desktop tests

- `npm test` in `desktop/` uses Node type stripping. Value imports in any module a test loads need the `.ts` extension plus the repo's `// @ts-ignore Node type stripping requires explicit TypeScript extension.` line; type-only imports need neither. A tested module cannot import tsup-only modules (for example `native-runtime.ts`); inject the value instead. A polling timer left running hangs the test process, so give each test its own state and dispose it in `t.after`.
